10.2 进阶应用：弱网优化与降级策略 ​

弱网下用户体验的保障方案：从自动降码率到手动降级到 RTMP 兜底。

10.2.1 弱网的 5 个等级与对应策略 ​

等级丢包率延迟 RTT策略
A（优秀）< 1%< 50ms最佳质量（1080p/30fps）
B（良好）1~3%50~150ms正常质量（720p/30fps）
C（一般）3~8%150~300ms降码率 + 降分辨率
D（较差）8~15%300~600ms进一步降码率 + 降帧率（15fps）
E（极差）> 15%> 600ms降级策略（见下）

10.2.2 降级策略（当 WebRTC 无法维持时） ​

策略 1：自动切换到 HLS 低延迟流 ​

用户进直播间 → 默认 WebRTC 拉流（低延迟）
                    │
                    ├── 5 秒内 ICE 连接失败 ──► 自动降级 HLS
                    ├── 丢包率 > 15% 持续 30 秒 ──► 自动降级 HLS
                    └── 用户手动点"切换低延迟 / 高清"
js
let currentStream = 'webrtc'

async function ensureQuality() {
  const stats = await pc.getStats()
  // ... 获取丢包率 ...
  
  if (packetLoss > 0.15 && currentStream === 'webrtc') {
    showSwitchingUI()  // 提示"网络较差，正在切换..."
    switchToHLS()
  }
}

策略 2：清晰度自适应切换 ​

1080p → 720p → 480p → 360p
  ↑                          │
  └──────────────────────────┘
     网络好时逐步升回去

关键是升比降慢：降码率要快（几秒钟内），升码率要慢（每次升一档间隔 30 秒以上），防止网络抖动。

策略 3：音频优先 + 视频关闭 ​

弱网到一定程度 → 视频轨道 enabled=false，只留音频
                     │
                     └── 音频用 Opus + FEC + 低码率（24~32kbps）
                         Opus 在弱网下仍然能清晰听清

策略 4：TURN 兜底 ​

ICE 直连和 STUN 都失败时，最后靠 TURN 中继：

  • 延迟略增（30~80ms），但至少能通
  • TURN 带宽成本高（流量翻倍），但比用户流失好

10.2.3 客户端 QoE 监控面板 ​

实时显示当前 WebRTC 链路质量，用户可以看到"我这路现在卡不卡"：

指标好一般差显示
发送码率> 1Mbps300k~1M< 300k绿 / 黄 / 红
接收丢包率< 1%1~5%> 5%绿 / 黄 / 红
接收分辨率≥ 720p480p< 480p文字显示
接收帧率≥ 25fps15~24< 15文字显示
RTT< 100ms100~300> 300绿 / 黄 / 红
网络类型5G/WiFi4G3G/有线差文字显示

把 QoE 指标展示给用户，既能减少客诉，也能引导用户理解"我的网络就是不行"。

10.2.4 小结 ​

你应该记住
弱网分等级处理A→E，对应不同策略
降级优先 WebRTC 内部调节GCC 自动降码率 → simulcast 降分辨率 → 降帧率 → 只音频 → 切换 HLS
升码率慢、降码率快防止网络抖动导致频繁切换
TURN 是最后兜底成本高但必须有
把 QoE 展示给用户减少客诉，增强信任感
