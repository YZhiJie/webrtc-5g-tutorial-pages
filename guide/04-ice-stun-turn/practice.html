4.3 实战案例：搭建 Coturn TURN 服务器 ​

Coturn 是业界最主流的开源 TURN 服务器（用于 WebRTC 的 NAT 穿透中继）。本章节从零搭建、配置、验证。

4.3.1 为什么需要自己的 TURN ​

  • 免费公共 STUN 服务器可用（Google 提供），但公共 TURN 服务器几乎没有（因为带宽成本高）
  • 生产环境必须自建 TURN，否则用户穿透失败就会看到黑屏
  • 5G 对称 NAT 场景下，TURN 是必经之路

4.3.2 安装 Coturn ​

macOS（开发测试） ​

bash
brew install coturn

# 配置文件在 /usr/local/etc/turnserver.conf
# 启动
turnserver -c /usr/local/etc/turnserver.conf

Ubuntu / Debian（生产） ​

bash
sudo apt-get update
sudo apt-get install -y coturn

# 配置文件在 /etc/turnserver.conf
sudo systemctl enable coturn
sudo systemctl start coturn

Docker（推荐，最简） ​

bash
docker run -d --name coturn \
  -p 3478:3478 \
  -p 3478:3478/udp \
  -p 49152-65535:49152-65535/udp \
  -e TURN_USER=webrtc \
  -e TURN_PASSWORD=webrtc2024 \
  instrumentisto/coturn

4.3.3 核心配置 ​

ini
# /etc/turnserver.conf

# Listening port
listening-port=3478
tls-listening-port=5349

# 监听网卡（0.0.0.0 全部）
listening-ip=0.0.0.0
# 如果有公网 IP，写在这里；NAT 后的话写内网 IP
# external-ip=YOUR_PUBLIC_IP

# 用户名密码（生产应该用数据库/Redis）
user=webrtc:webrtc2024

# 认证
no-auth=false
fingerprint

# 允许 relay 的 IP 范围（全部）
no-multicast-peers

# 日志
verbose
log-file=/var/log/turnserver.log
simple-log

# 中继端口范围（防火墙放行）
min-port=49152
max-port=65535

# NAT 穿透增强
stun-only=false          # false = 同时做 STUN 和 TURN
no-stdout-log

# 5G / IPv6 支持
# ipv6                 # 开 IPv6 监听
# external-ipv6=YOUR_IPV6_ADDR

4.3.4 防火墙放行 ​

bash
# Ubuntu ufw
sudo ufw allow 3478/tcp
sudo ufw allow 3478/udp
sudo ufw allow 5349/tcp      # TURNS
sudo ufw allow 49152:65535/udp  # relay 端口范围

# CentOS firewalld
sudo firewall-cmd --add-port=3478/tcp --permanent
sudo firewall-cmd --add-port=3478/udp --permanent
sudo firewall-cmd --add-port=49152-65535/udp --permanent
sudo firewall-cmd --reload

云平台（AWS / 阿里云）还需要在安全组放同样的端口。

4.3.5 WebRTC 客户端配置 ​

js
const pc = new RTCPeerConnection({
  iceServers: [
    // 公共 STUN（免费，够用）
    { urls: 'stun:stun.l.google.com:19302' },
    { urls: 'stun:stun1.l.google.com:19302' },
    
    // 你的 Coturn TURN
    {
      urls: [
        'turn:your-turn-server.com:3478',
        'turn:your-turn-server.com:3478?transport=udp',
        'turn:your-turn-server.com:3478?transport=tcp',
        'turns:your-turn-server.com:5349',  // TURNS 加密版
      ],
      username: 'webrtc',
      credential: 'webrtc2024',
    },
  ],
  // 'all' = 先试直连/STUN，失败了才用 TURN
  // 'relay' = 强制只走 TURN（排查时用）
  iceTransportPolicy: 'all',
})

4.3.6 验证 TURN 服务器 ​

浏览器端测试 ​

html
<script>
const pc = new RTCPeerConnection({
  iceServers: [
    { urls: 'stun:stun.l.google.com:19302' },
    { urls: 'turn:your-turn-server.com:3478', username: 'webrtc', credential: 'webrtc2024' }
  ]
})

pc.addEventListener('icecandidate', (e) => {
  if (e.candidate) {
    console.log(e.candidate.candidate)
    // 你应该能看到 typ relay 的候选
    // 如 "candidate:... typ relay raddr ..."
  }
})

// 触发候选收集
pc.createDataChannel('test')
pc.createOffer().then(o => pc.setLocalDescription(o))
</script>

命令行测试（turnutils_uclient） ​

bash
# Coturn 自带测试工具
turnutils_uclient -u webrtc -w webrtc2024 your-turn-server.com

4.3.7 生产环境注意事项 ​

项建议
带宽每并发用户约 1~3 Mbps 上行（主播推流），TURN 服务器带宽要按峰值 ×2 算
负载单台 Coturn 约支持 5000~10000 并发（取决于带宽和 CPU）
分布式多台 TURN 做 DNS 轮询或 Nginx 负载均衡
动态密钥用短期凭证（TURN REST API）而不是硬编码密码
日志监控tail -f turnserver.log 观察 relay 流量
成本TURN 流量是 P2P 时的 2 倍（进出都经 TURN），要优化 ICE 穿透率
