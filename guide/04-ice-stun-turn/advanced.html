4.2 进阶应用：ICE 候选收集与连通性检查 ​

深入 ICE 候选格式、Trickle ICE、5G 网络下的 NAT 新特性。

4.2.1 ICE 候选 SDP 格式 ​

每个候选会以 a=candidate: 行的形式出现在 SDP 中：

a=candidate:1 1 UDP 2130706431 192.168.1.100 56789 typ host
│            │ │ │           │               │          │  │
│            │ │ │           │               │          │  └─ 候选类型 (host)
│            │ │ │           │               │          └──── 端口号
│            │ │ │           │               └────────────────── IP 地址
│            │ │ │           └─────────────────────────────────── 优先级（越大越优先）
│            │ │ └─────────────────────────────────────────────── 协议（UDP/TCP）
│            │ └────────────────────────────────────────────────── 组件 ID（1=RTP, 2=RTCP）
│            └──────────────────────────────────────────────────── foundation ID
└─ 前缀

其他类型的候选：

a=candidate:2 1 UDP 1694498815 114.242.34.5 50000 typ srflx raddr 192.168.1.100 rport 56789
                                                                              ↑ STUN 反射地址的原始 IP 和端口

a=candidate:3 1 UDP 11337 34.56.78.90 49170 typ relay raddr 114.242.34.5 rport 50000
                                                                   ↑ TURN 中继地址对应的 peer reflexive 地址

优先级计算（简化）：

priority = type_pref × 2^24 + local_pref × 2^8 + (256 - component)
类型type_pref
Host126
Peer-Reflexive110
Server-Reflexive (srflx)100
Relayed (relay)0

4.2.2 Trickle ICE（增量候选） ​

传统 ICE 是等所有候选收集完再一次性发 SDP（iceGatheringState === 'complete'）。Trickle ICE 是收集到一个就发一个，加速连接建立。

js
// 传统方式（等全部收集完）
const offer = await pc.createOffer()
await pc.setLocalDescription(offer)

// 监听 ICE 收集完成
pc.addEventListener('icegatheringstatechange', () => {
  if (pc.iceGatheringState === 'complete') {
    // 此时 pc.localDescription.sdp 已包含所有候选
    signaling.send(pc.localDescription.sdp)
  }
})

// Trickle ICE（推荐，逐个发送）
pc.addEventListener('icecandidate', (e) => {
  if (e.candidate) {
    // 每收集到一个候选就通过信令发送
    signaling.send({
      type: 'ice-candidate',
      candidate: e.candidate
    })
  } else {
    // null 表示收集完毕
    signaling.send({ type: 'ice-done' })
  }
})

现代 WebRTC 默认就是 Trickle ICE，浏览器会自动启用。不要关闭它。

4.2.3 5G 网络下的 NAT 新特性 ​

5G 核心网（5GC）引入了几种影响 ICE 的新因素：

特性对 WebRTC 的影响
IPv6-only 网络部分 5G 运营商只分配 IPv6 地址 → STUN/TURN 必须支持 IPv6 候选
5G CGN运营商级 NAT（Carrier-Grade NAT）通常是对称 NAT（类型 4） → 必须用 TURN
网络切片每个切片可能有独立的 NAT → 候选收集时要注意多网络接口
移动性管理5G 的快速重传导致 NAT 端口映射变化更快 → 需要更频繁的 ICE 重收集
UPF 下沉用户面功能（UPF）靠近基站 → 如果 TURN 也部署在 MEC，Relayed 候选延迟可以很低

5G 场景下的推荐 TURN 配置：

js
const pc = new RTCPeerConnection({
  iceServers: [
    // STUN（收集反射地址）
    { urls: 'stun:stun.l.google.com:19302' },
    { urls: 'stun:stun1.l.google.com:19302' },
    // IPv6 友好的 STUN
    { urls: 'stun:stun6.l.google.com:19302' },
    
    // TURN（5G 场景下必须有）
    {
      urls: 'turn:turn.yourdomain.com:3478',
      username: 'user',
      credential: 'pass',
      // 同时用 UDP 和 TCP/TLS
    },
    // TURNS（TURN over TLS，绕过企业防火墙）
    {
      urls: 'turns:turn.yourdomain.com:5349',
      username: 'user',
      credential: 'pass',
    },
  ],
  iceTransportPolicy: 'all',  // 'all'=先试直连再转 TURN; 'relay'=强制只走 TURN
})
