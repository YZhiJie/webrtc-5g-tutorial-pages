6.1 基础入门：5G URLLC / eMBB / mMTC ​

5G 三大场景如何重塑 WebRTC 实时互动直播的技术选型与部署架构。

6.1.1 5G 三大场景速览 ​

场景全称核心 KPIWebRTC 适配
eMBBEnhanced Mobile Broadband峰值 20Gbps / 用户 100Mbps4K/8K 直播成为常规；上行 10Gbps 峰值让手机也能推 4K
URLLCUltra-Reliable Low Latency Communications端到端 ≤ 1ms / 可靠性 ≥ 99.999%空口时延从 4G 的 30~50ms 降到 1~10ms
mMTCMassive Machine-Type Communications百万连接/km²IoT 监控设备接入 WebRTC 成本骤降

WebRTC 实时互动直播主要受益于 eMBB + URLLC 的组合拳。

6.1.3 5G 网络切片（Network Slicing） ​

运营商可以把一张物理 5G 网络切成多张逻辑独立的虚拟网络，每张有独立的 SLA。WebRTC 直播可以申请一张专属切片：

┌──────────────────────────────────────────────────┐
│                 物理 5G 网络                      │
├──────────┬──────────┬──────────┬─────────────────┤
│ 切片 A   │ 切片 B   │ 切片 C   │ 切片 D          │
│ WebRTC   │ IoT      │ 自动驾驶 │ 普通移动宽带      │
│ 直播     │          │          │                  │
│ QFI=101  │ QFI=102  │ QFI=103  │ QFI=104         │
│ 高优先级 │ 低功耗   │ 极低时延 │ 大带宽          │
└──────────┴──────────┴──────────┴─────────────────┘

客户端通过 5G QoS Flow Identifier (QFI) 标识自己在哪个切片里。WebRTC 可以据此做差异化调度。

6.1.4 移动边缘计算（MEC） ​

5G 把计算和 CDN 节点下沉到基站侧（通常距离终端 1~2 跳）：

传统 WebRTC 直播：
手机 → 基站 → 核心网 → 骨干网 → 中心机房 SFU → 骨干网 → ... → 观众
                                                  ↑ 延迟 50~100ms

5G MEC 架构：
手机 → 基站 → 边缘 SFU（就在基站机房） → 边缘 CDN → ... → 观众
                  ↑ 减少 3~5 跳，省 50~100ms

MEC 还能做：

  • 边缘转码（主播推一路，边缘实时转多路给不同带宽观众）
  • 边缘录制（省中心机房存储）
  • 边缘 AI（美颜、背景分割实时跑在边缘 GPU 上）

6.1.5 小结 ​

概念一句话
eMBB大带宽让 4K/60fps 直播成为手机标配
URLLC1ms 空口时延是直播互动的基石
切片运营商为 WebRTC 开辟 QoS 保障通道
MECSFU/转码/AI 下沉到基站，省延迟
5G CGN运营商级 NAT 仍然存在，TURN 不能少
