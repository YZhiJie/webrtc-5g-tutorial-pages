3.2 进阶应用：能力协商与编码参数调优 ​

深入 SDP 格式、编解码器优先级策略、5G 场景下的编码参数动态调优。

3.2.1 SDP 编解码协商细节 ​

SDP（Session Description Protocol）是 WebRTC 用来交换能力的核心格式。一段典型的视频 SDP：

m=video 9 UDP/TLS/RTP/SAVPF 96 98 100
│     │ │           │         │   │   │
│     │ │           │         │   │   └─ 编解码器 ID 100 = H264
│     │ │           │         │   └───── 编解码器 ID 98 = VP9
│     │ │           │         └───────── 编解码器 ID 96 = VP8
│     │ │           └────────── RTP 负载类型（动态分配）
│     │ └─────────────────────── DTLS 加密后用 SRTP
│     └───────────────────────── UDP 传输（回退 TCP 时有不同 SDP）
└─ m=media 类型（audio/video/application）

a=rtpmap:96 VP8/90000        ← ID 96 映射到 VP8，时钟频率 90kHz
a=rtpmap:98 VP9/90000        ← ID 98 映射到 VP9
a=rtpmap:100 H264/90000      ← ID 100 映射到 H264

a=fmtp:100 level-asymmetry-allowed=1;packetization-mode=1;profile-level-id=42001f
│     │   │                              │                    │
│     │   │                              │                    └─ profile-level-id
│     │   │                              └─ H264 打包模式（1=非交织）
│     │   └─ level-asymmetry-allowed（允许不对称编码等级）
│     └─ fmtp 参数（H264 特有）
└─ fmtp 行（format parameters）

Chrome 会按 SDP 中出现的顺序自动设置优先级——写在最前面的优先级最高。

3.2.2 自定义编解码器优先级 ​

在 SDP 生成后修改顺序：

js
// 强制 H264 优先于 VP8
function prioritizeH264(sdp) {
  // 取出 m=video 段
  const lines = sdp.split('\r\n')
  const videoStart = lines.findIndex(l => l.startsWith('m=video'))
  
  // 修改 m=video 行的编解码器 ID 顺序
  // 原来: m=video 9 UDP/TLS/RTP/SAVPF 96 98 100  (VP8 VP9 H264)
  // 改后: m=video 9 UDP/TLS/RTP/SAVPF 100 96 98  (H264 VP8 VP9)
  const mLine = lines[videoStart]
  const parts = mLine.split(' ')
  const codecIds = parts.slice(4)  // 取出所有 ID
  
  // 把 H264 ID（100）移到最前面
  const h264Id = codecIds.find(id => {
    const idx = lines.findIndex((l, i) => i > videoStart && l.startsWith(`a=rtpmap:${id} H264`))
    return idx !== -1
  })
  if (h264Id) {
    const rest = codecIds.filter(id => id !== h264Id)
    parts.splice(4, codecIds.length, h264Id, ...rest)
    lines[videoStart] = parts.join(' ')
  }
  
  return lines.join('\r\n')
}

// 使用
let offer = await pc.createOffer()
offer.sdp = prioritizeH264(offer.sdp)
await pc.setLocalDescription(offer)

3.2.3 5G 场景下的编码策略 ​

5G 大带宽 + 低时延特性下，可以调整默认编码策略：

参数4G 默认值5G 优化值原因
最小码率 minBitrate300kbps800kbps5G 带宽足，维持更高画质下限
最大码率 maxBitrate2Mbps4~8Mbps5G 支持 1080p/60fps
帧率 maxFramerate3060eMBB 支持高帧率
分辨率1280×7201920×1080上行增强支持 1080p
关键帧间隔由编码器决定2~4 秒网络好时减少关键帧频率，省带宽
FEC 冗余度默认降低5G 丢包率低，不需要太多冗余
simulcast 层数3 层（h/m/l）可减到 2 层5G 带宽均匀，不需要太多档位

实用策略 ​

js
// 检测两端共同支持的最高效编解码器
function negotiateBestCodec(localSdp, remoteSdp) {
  const preferList = ['AV1', 'VP9', 'H264', 'VP8']
  
  for (const codec of preferList) {
    if (sdpHasCodec(localSdp, codec) && sdpHasCodec(remoteSdp, codec)) {
      return codec
    }
  }
  return 'H264'  // 兜底
}
